# รายงานการวิเคราะห์และออกแบบระบบยืม-คืนอุปกรณ์ห้องปฏิบัติการออนไลน์

---

## ส่วนที่ 2: WBS และ Gantt Chart (20 คะแนน)

### Work Breakdown Structure (WBS)
1. การศึกษารวบรวมความต้องการ (Requirements Gathering)
   1.1 สัมภาษณ์นักศึกษา อาจารย์ และเจ้าหน้าที่
   1.2 รวบรวมและวิเคราะห์เงื่อนไขการยืม-คืน
2. การวิเคราะห์และออกแบบระบบ (System Analysis & Design)
   2.1 จัดทำ Problem Statement และ Stakeholder Analysis
   2.2 กำหนด Functional และ Non-Functional Requirements
   2.3 เขียน Context Diagram, DFD Level 1 และ DFD Level 2
3. การพัฒนาระบบ (System Development)
   3.1 พัฒนาระบบส่วนผู้ใช้งานและเจ้าหน้าที่
   3.2 เชื่อมต่อระบบพิสูจน์ตัวตนด้วยบัญชีมหาวิทยาลัย
4. การทดสอบและการส่งมอบ (Testing & Deployment)
   4.1 ทดสอบระบบ (Unit Test / Integration Test)
   4.2 ทำคู่มือและส่งมอบระบบ

## ส่วนที่ 3: วิเคราะห์ปัญหาและ Requirement (25 คะแนน)

### 3.1 Problem Statement
* **ผู้ประสบปัญหา:** นักศึกษา อาจารย์ และเจ้าหน้าที่ห้องปฏิบัติการ
* **ปัญหาปัจจุบัน:** ผู้ขอยืมต้องสอบถามเจ้าหน้าที่เพื่อดูว่าอุปกรณ์ว่างหรือไม่ แล้วกรอกแบบฟอร์มกระดาษ ทำให้เสียเวลาและเกิดการจองซ้ำซ้อน
* **สาเหตุหรือข้อจำกัด:** ไม่มีระบบตรวจสอบสถานะอุปกรณ์แบบ Real-time และการจัดการข้อมูลกระดาษไม่มีประสิทธิภาพ
* **ผลลัพธ์ที่ระบบใหม่ควรช่วย:** ช่วยให้ผู้ใช้ค้นหา คัดกรอง และส่งคำขอยืมออนไลน์ได้ทันที พร้อมแสดงสถานะอุปกรณ์ที่ว่างจริง
* **เกณฑ์ความสำเร็จ (Key Metric):** ลดเวลาในการทำรายการยืม-คืนอุปกรณ์ลงได้มากกว่า 50% และอัตราการจองอุปกรณ์ซ้ำซ้อนเป็น 0%

### 3.2 Stakeholder Analysis
1. **นักศึกษา / อาจารย์ (ผู้ใช้งานทั่วไป):**
   * *วิธีเก็บข้อมูล:* แจกแบบสอบถามออนไลน์ และสัมภาษณ์ตัวแทนผู้ใช้งานเกี่ยวกับความสะดวกและขั้นตอนการยืม
2. **เจ้าหน้าที่ห้องปฏิบัติการ (ผู้ดูแลระบบ):**
   * *วิธีเก็บข้อมูล:* การสัมภาษณ์เชิงลึก (In-depth Interview) เกี่ยวกับขั้นตอนอนุมัติ การรับคืน และปัญหาที่พบบ่อย
3. **ผู้ดูแลระบบ IT มหาวิทยาลัย (System Administrator):**
   * *วิธีเก็บข้อมูล:* ประชุมหารือข้อกำหนดทางเทคนิคในการเชื่อมต่อระบบพิสูจน์ตัวตน (Authentication) กับบัญชีมหาวิทยาลัย

### 3.3 Functional Requirements (6 ข้อ)
* **FR-01:** ระบบต้องสามารถยืนยันตัวตนผู้ใช้งานด้วยบัญชีมหาวิทยาลัยได้
* **FR-02:** ระบบต้องสามารถค้นหาอุปกรณ์ตามประเภท และแสดงเฉพาะอุปกรณ์ที่ว่างตามช่วงเวลาที่ระบุได้
* **FR-03:** ระบบต้องรองรับการส่งคำขอยืม โดยต้องระบุ วันยืม, วันคืน และวัตถุประสงค์
* **FR-04:** ระบบต้องไม่อนุญาตให้ยืมอุปกรณ์เกิน 3 รายการ หรือยืมเกิน 7 วัน ต่อครั้ง[cite: 1, 2]
* **FR-05:** ระบบต้องส่งคำขอยืมกล้องถ่ายภาพและ Notebook ให้เจ้าหน้าที่อนุมัติ ส่วนอุปกรณ์ทั่วไปให้อนุมัติอัตโนมัติหากว่าง
* **FR-06:** ระบบต้องบันทึกสภาพอุปกรณ์เมื่อรับคืน (`ปกติ`, `ชำรุด`, `สูญหาย`) และระงับสิทธิ์การยืมใหม่กรณีคืนเกินกำหนด[cite: 1, 2]

### 3.4 Non-Functional Requirements (3 ข้อ)
* **NFR-01 (Performance):** ระบบต้องค้นหาและแสดงสถานะอุปกรณ์ว่างได้ภายในเวลาไม่เกิน 2 วินาที ณ ช่วงเวลาที่มีผู้เข้าใช้งานพร้อมกัน 100 ราย
* **NFR-02 (Security):** การรับส่งข้อมูลผ่านระบบต้องใช้นวัตกรรมการเข้ารหัสผ่าน HTTPS และการยืนยันตัวตนผ่าน OAuth/SSO ของมหาวิทยาลัยเท่านั้น[cite: 1, 2]
* **NFR-03 (Usability):** ผู้ใช้ใหม่ต้องสามารถทำรายการยืมอุปกรณ์สำเร็จได้ภายใน 3 นาที โดยไม่ต้องผ่านการอบรมการใช้งาน
