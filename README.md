# รายงานการวิเคราะห์และออกแบบระบบยืม-คืนอุปกรณ์ห้องปฏิบัติการออนไลน์

---

## ส่วนที่ 2: WBS และ Gantt Chart (20 คะแนน)

### Work Breakdown Structure (WBS)
1. การศึกษารวบรวมความต้องการ (Requirements Gathering)
   1.1 สัมภาษณ์นักศึกษา อาจารย์ และเจ้าหน้าที่
   1.2 รวบรวมและวิเคราะห์เงื่อนไขการยืม-คืน
2. การวิเคราะห์และออกแบบระบบ (System Analysis & Design)
   2.1 จัดทำ Problem Statement และ Stakeholder Analysis
   2.2 กำหนด Functional และ Non-Functional Requirements
   2.3 เขียน Context Diagram, DFD Level 1 และ DFD Level 2
3. การพัฒนาระบบ (System Development)
   3.1 พัฒนาระบบส่วนผู้ใช้งานและเจ้าหน้าที่
   3.2 เชื่อมต่อระบบพิสูจน์ตัวตนด้วยบัญชีมหาวิทยาลัย
4. การทดสอบและการส่งมอบ (Testing & Deployment)
   4.1 ทดสอบระบบ (Unit Test / Integration Test)
   4.2 ทำคู่มือและส่งมอบระบบ

## ส่วนที่ 3: วิเคราะห์ปัญหาและ Requirement (25 คะแนน)

### 3.1 Problem Statement
* **ผู้ประสบปัญหา:** นักศึกษา อาจารย์ และเจ้าหน้าที่ห้องปฏิบัติการ
* **ปัญหาปัจจุบัน:** ผู้ขอยืมต้องสอบถามเจ้าหน้าที่เพื่อดูว่าอุปกรณ์ว่างหรือไม่ แล้วกรอกแบบฟอร์มกระดาษ ทำให้เสียเวลาและเกิดการจองซ้ำซ้อน
* **สาเหตุหรือข้อจำกัด:** ไม่มีระบบตรวจสอบสถานะอุปกรณ์แบบ Real-time และการจัดการข้อมูลกระดาษไม่มีประสิทธิภาพ
* **ผลลัพธ์ที่ระบบใหม่ควรช่วย:** ช่วยให้ผู้ใช้ค้นหา คัดกรอง และส่งคำขอยืมออนไลน์ได้ทันที พร้อมแสดงสถานะอุปกรณ์ที่ว่างจริง
* **เกณฑ์ความสำเร็จ (Key Metric):** ลดเวลาในการทำรายการยืม-คืนอุปกรณ์ลงได้มากกว่า 50% และอัตราการจองอุปกรณ์ซ้ำซ้อนเป็น 0%

### 3.2 Stakeholder Analysis
1. **นักศึกษา / อาจารย์ (ผู้ใช้งานทั่วไป):**
   * *วิธีเก็บข้อมูล:* แจกแบบสอบถามออนไลน์ และสัมภาษณ์ตัวแทนผู้ใช้งานเกี่ยวกับความสะดวกและขั้นตอนการยืม
2. **เจ้าหน้าที่ห้องปฏิบัติการ (ผู้ดูแลระบบ):**
   * *วิธีเก็บข้อมูล:* การสัมภาษณ์เชิงลึก (In-depth Interview) เกี่ยวกับขั้นตอนอนุมัติ การรับคืน และปัญหาที่พบบ่อย
3. **ผู้ดูแลระบบ IT มหาวิทยาลัย (System Administrator):**
   * *วิธีเก็บข้อมูล:* ประชุมหารือข้อกำหนดทางเทคนิคในการเชื่อมต่อระบบพิสูจน์ตัวตน (Authentication) กับบัญชีมหาวิทยาลัย

### 3.3 Functional Requirements (6 ข้อ)
* **FR-01:** ระบบต้องสามารถยืนยันตัวตนผู้ใช้งานด้วยบัญชีมหาวิทยาลัยได้
* **FR-02:** ระบบต้องสามารถค้นหาอุปกรณ์ตามประเภท และแสดงเฉพาะอุปกรณ์ที่ว่างตามช่วงเวลาที่ระบุได้
* **FR-03:** ระบบต้องรองรับการส่งคำขอยืม โดยต้องระบุ วันยืม, วันคืน และวัตถุประสงค์
* **FR-04:** ระบบต้องไม่อนุญาตให้ยืมอุปกรณ์เกิน 3 รายการ หรือยืมเกิน 7 วัน ต่อครั้ง
* **FR-05:** ระบบต้องส่งคำขอยืมกล้องถ่ายภาพและ Notebook ให้เจ้าหน้าที่อนุมัติ ส่วนอุปกรณ์ทั่วไปให้อนุมัติอัตโนมัติหากว่าง
* **FR-06:** ระบบต้องบันทึกสภาพอุปกรณ์เมื่อรับคืน (`ปกติ`, `ชำรุด`, `สูญหาย`) และระงับสิทธิ์การยืมใหม่กรณีคืนเกินกำหนด

### 3.4 Non-Functional Requirements (3 ข้อ)
* **NFR-01 (Performance):** ระบบต้องค้นหาและแสดงสถานะอุปกรณ์ว่างได้ภายในเวลาไม่เกิน 2 วินาที ณ ช่วงเวลาที่มีผู้เข้าใช้งานพร้อมกัน 100 ราย
* **NFR-02 (Security):** การรับส่งข้อมูลผ่านระบบต้องใช้นวัตกรรมการเข้ารหัสผ่าน HTTPS และการยืนยันตัวตนผ่าน OAuth/SSO ของมหาวิทยาลัยเท่านั้น
* **NFR-03 (Usability):** ผู้ใช้ใหม่ต้องสามารถทำรายการยืมอุปกรณ์สำเร็จได้ภายใน 3 นาที โดยไม่ต้องผ่านการอบรมการใช้งาน
## ส่วนที่ 4: Context Diagram 
### รายละเอียดองค์ประกอบในแผนภาพ (Data Flow Description)

#### 1. System Process
* **0. ระบบยืม-คืนอุปกรณ์ห้องปฏิบัติการออนไลน์**

#### 2. External Entities (องค์ประกอบภายนอก)
1. **ผู้ใช้งาน (นักศึกษา/อาจารย์)**
2. **เจ้าหน้าที่ห้องปฏิบัติการ**
3. **ระบบยืนยันตัวตนมหาวิทยาลัย**

#### 3. รายละเอียดการไหลของข้อมูล (Data Flow / Input-Output)

* **ผู้ใช้งาน (นักศึกษา/อาจารย์)**
  * **Input (เข้าสู่ระบบ):** ข้อมูลการเข้าสู่ระบบ (บัญชี ม.), เงื่อนไขการค้นหาอุปกรณ์, ข้อมูลคำขอยืม (เลือกอุปกรณ์, วันยืม-คืน, วัตถุประสงค์)
  * **Output (ออกจากระบบ):** ผลการล็อกอิน, รายการอุปกรณ์ที่ว่างตามช่วงเวลา, สถานะการอนุมัติ/ปฏิเสธคำขอ, ประวัติการยืม-คืน

* **เจ้าหน้าที่ห้องปฏิบัติการ**
  * **Input (เข้าสู่ระบบ):** ผลการอนุมัติ/ปฏิเสธคำขอ (กล้อง/Notebook), บันทึกการรับคืนและสภาพอุปกรณ์ (ปกติ/ชำรุด/สูญหาย), การจัดการข้อมูลอุปกรณ์ (เพิ่ม/แก้ไข/ปิดใช้งาน)
  * **Output (ออกจากระบบ):** รายการคำขอที่รออนุมัติ, รายการอุปกรณ์ที่กำลังถูกยืม, รายงานแจ้งเตือนการคืนเกินกำหนด

* **ระบบยืนยันตัวตนมหาวิทยาลัย**
  * **Input (เข้าสู่ระบบ):** ผลการตรวจสอบสิทธิ์และข้อมูลผู้ใช้งาน (User Profile / Auth Token)
  * **Output (ออกจากระบบ):** คำขอตรวจสอบสิทธิ์ (User Credentials)
 

     ## ส่วนที่ 5: DFD Level 1 (25 คะแนน)
### รายละเอียดองค์ประกอบในแผนภาพ (Data Flow Diagram Level 1)

#### 1. Data Stores (ฐานข้อมูลในระบบ)
* **D1: ผู้ใช้งาน** - เก็บข้อมูลนักศึกษา อาจารย์ เจ้าหน้าที่ และสิทธิ์การใช้งาน
* **D2: อุปกรณ์** - เก็บรายละเอียด รายการอุปกรณ์ สถานะความพร้อม และประเภทอุปกรณ์
* **D3: รายการยืม-คืน** - เก็บประวัติคำขอยืม วันที่ยืม-กำหนดคืน วัตถุประสงค์ และสถานะการอนุมัติ/การคืน

#### 2. Processes (กระบวนการหลัก 5 ขั้นตอน)

1. **1.0 ยืนยันตัวตนผู้ใช้ (Authentication):**
   * รับข้อมูลการเข้าสู่ระบบจากผู้ใช้งาน ตรวจสอบสิทธิ์ร่วมกับระบบมหาวิทยาลัย บันทึกสิทธิ์ลง `D1: ผู้ใช้งาน` และคืนผลการล็อกอิน
2. **2.0 ค้นหาและตรวจสอบสถานะอุปกรณ์ (Search & Check Status):**
   * รับเงื่อนไขการค้นหาจากผู้ใช้งาน ดึงข้อมูลจาก `D2: อุปกรณ์` และเช็กประวัติจาก `D3: รายการยืม-คืน` เพื่อแสดงอุปกรณ์ที่ว่างจริง
3. **3.0 จัดการคำขอยืมอุปกรณ์ (Manage Borrowing Request):**
   * รับคำขอยืม ตรวจสอบเงื่อนไขการยืม (ไม่เกิน 3 ชิ้น / 7 วัน) และบันทึกคำขอลง `D3: รายการยืม-คืน`
4. **4.0 พิจารณาอนุมัติคำขอ (Approve Request):**
   * เจ้าหน้าที่รับรายการรออนุมัติ (กล้อง/Notebook) และบันทึกผลการอนุมัติ/ปฏิเสธ อัปเดตสถานะลง `D3: รายการยืม-คืน`
5. **5.0 บันทึกรับคืนและจัดการอุปกรณ์ (Manage Return):**
   * เจ้าหน้าที่บันทึกการรับคืนและสภาพอุปกรณ์ (`ปกติ`, `ชำรุด`, `สูญหาย`) เพื่ออัปเดตสถานะใน `D3: รายการยืม-คืน` และอัปเดตสถานะความพร้อมใช้งานใน `D2: อุปกรณ์`


## ส่วนที่ 6: DFD Level 2 - Process 3.0 (25 คะแนน)
### รายละเอียดขั้นตอนการทำงาน (Sub-Processes)

ในกระบวนการ **3.0 จัดการคำขอยืมอุปกรณ์** จะแบ่งการทำงานออกเป็น 5 กระบวนการย่อย เพื่อควบคุมเงื่อนไขและกฎการยืมตามข้อกำหนดของระบบ ดังนี้:

* **3.1 ตรวจสอบสิทธิ์และประวัติผู้ใช้ (Check User Eligibility):**
  * รับข้อมูลผู้ยืม และอ่านข้อมูลสิทธิ์ใช้งานจาก `D1: ผู้ใช้งาน` 
  * ตรวจสอบว่าผู้ใช้มีสถานะปกติ และไม่มีประวัติการค้างส่งอุปกรณ์เกินกำหนด

* **3.2 ตรวจสอบจำนวนและระยะเวลาการยืม (Check Borrow Limits):**
  * ตรวจสอบเงื่อนไขข้อจำกัดของระบบ (System Constraints)
  * กำหนดสิทธิ์ให้ยืมอุปกรณ์ได้ **ไม่เกิน 3 ชิ้น** และระยะเวลาการยืม **ไม่เกิน 7 วัน**

* **3.3 ตรวจสอบประเภทและเงื่อนไขอุปกรณ์ (Check Equipment Type):**
  * อ่านข้อมูลประเภทอุปกรณ์จาก `D2: อุปกรณ์`
  * จำแนกประเภทอุปกรณ์ว่าเป็น **"อุปกรณ์ทั่วไป"** หรือ **"อุปกรณ์พิเศษ"** (เช่น กล้องถ่ายภาพ, Notebook)

* **3.4 อนุมัติการยืมอัตโนมัติ (Auto Approval):**
  * กรณีเป็น **อุปกรณ์ทั่วไป** และผ่านเงื่อนไขในข้อ 3.1-3.2 ระบบจะทำการอนุมัติคำขอให้อัตโนมัติทันที
  * กำหนดสถานะเป็น `"อนุมัติแล้ว"` แล้วบันทึกข้อมูลลง `D3: รายการยืม-คืน`

* **3.5 ส่งคำขอรออนุมัติไปยังเจ้าหน้าที่ (Send to Staff Approval):**
  * กรณีเป็น **อุปกรณ์พิเศษ (กล้องถ่ายภาพ / Notebook)** ระบบจะไม่ทำการอนุมัติทันที
  * กำหนดสถานะเป็น `"รออนุมัติ"` แล้วบันทึกข้อมูลลง `D3: รายการยืม-คืน` เพื่อส่งต่อให้เจ้าหน้าที่พิจารณาใน Process 4.0 ต่อไป
